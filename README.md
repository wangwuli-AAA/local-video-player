# 本地放映室

只在本机运行的中文视频小程序。网页播放器复用 ArtPlayer，格式转换复用 FFmpeg，观看进度保存在本机 SQLite 数据库。

## 开始使用

从 GitHub 下载或克隆后，先安装 Node.js **24 或更新版本**，双击 **首次安装.cmd** 安装依赖及 FFmpeg，再双击 **启动.cmd**。已完成安装的本地目录可以直接启动。

浏览器会打开 **http://127.0.0.1:8765** 。建议使用最新版 Edge 或 Chrome；重复双击启动文件会打开已有服务。

1. 点击“添加视频”，选择文件夹、多个视频文件，或者每行粘贴一个完整路径。可以反复添加多个文件夹。
2. 在“全部视频”中点击视频，随后点击播放器的播放按钮。
3. 再次打开时自动恢复进度，也可以点击“从头播放”。“最近观看”按最后观看时间排列，每个视频保留一条记录。
4. 新增或移动文件后，点击搜索框右侧的刷新按钮，重新扫描已添加来源。

播放器右上角的“右侧铺满”会让视频占满侧栏以外的区域，左侧目录仍可展开和切换视频。再次点击“退出铺满”或按 Esc 恢复原布局，播放位置不变。在窄屏布局下，铺满模式使用整个窗口。播放器自身的全屏按钮仍可进入整个屏幕的全屏播放。

左侧“文件夹”按目录层级显示视频。点击箭头展开或收起，点击文件夹名称筛选该目录及所有子目录的视频，点击树中的视频进入播放器。文件夹内的搜索只匹配当前目录范围；点击“全部视频”或“最近观看”清除目录筛选。切换目录不会中断播放，续播和历史记录照常保存。

目录树以已添加的文件夹为起点；单独添加的视频按所在文件夹归类，重叠来源会合并。树中只展示已添加的根目录和包含已导入视频的子目录，不会浏览电脑上的其他文件。

打开或继续播放视频时，左侧会自动展开视频所在的各级目录，高亮对应视频；若它不在目录树的可见区域内，会滚动到该视频。这个定位只滚动目录树，不会改变列表筛选或播放位置。

原文件始终留在原位置，不会上传、改写或因移除记录而被删除。

## 格式转换

- 常见的 H.264／AAC MP4 和兼容 WebM 直接播放。格式检查较保守，其他视频会先转换。
- 不能直接播放的 MKV、AVI 等视频按需转换为 H.264／AAC MP4。首次等待转换完成，再点击播放；后续复用缓存。
- 同时只转换一个视频，其他任务排队。“转换任务”中可以查看进度、取消任务；收起播放器不会取消转换。
- 原文件大小或修改时间变化后，旧缓存不再用于播放，旧进度也会重置。
- “缓存管理”显示占用并清理所有转换副本和未完成任务。清理会停止当前播放，不会删除原视频或观看记录。
- 转换以 CPU 为主，大视频需要时间和额外磁盘空间；没有自动清理或容量上限，请按需清理缓存。
- 仅使用第一条非封面视频轨道和第一条音轨；第一版不提供字幕选择、内嵌字幕转换、多音轨切换或 DRM 解密。
- 如果检测为可直接播放、但浏览器仍报错，可以点击“转换后播放”。损坏或 FFmpeg 不支持的视频可能无法转换。

## 数据与退出

程序目录中的 `data/library.sqlite` 保存媒体来源、列表、进度及历史；`data/cache` 是转换副本；`data/server*.log` 是日志。

播放期间每 5 秒保存一次，暂停、切换视频和离开网页时补存。意外断电或强制终止时，通常最多丢失一个保存周期；服务不可用时页面会提示保存失败。浏览器清理网站数据不会删除数据库。

关闭网页后，本地服务会继续运行，转换也会继续。如果要退出服务，双击 **停止.cmd**。复制或备份数据库前先停止服务；最方便的备份方式是退出后复制整个 `data` 目录。

移除视频记录不会删除原文件；如果视频仍在已添加的文件夹中，下次刷新会重新导入。移除来源只停止未来扫描，已导入的视频和历史保留。文件被移动后按新路径导入，第一版不自动匹配或迁移旧记录。

## 首次安装或迁移

需要 Windows x64、Node.js **24 或更新版本**。在新电脑上安装 Node.js 后，双击 **首次安装.cmd**。脚本会安装锁定的 npm 依赖，并从 FFmpeg 官网列出的 Gyan Windows 构建源下载 FFmpeg／ffprobe，校验 SHA-256。安装需要联网；日常使用无需联网。

如果直接复制完整交付目录（含 `node_modules`、`bin`），无需重复下载依赖。迁移到另一台电脑后，原视频路径可能需要重新添加。

全部文件都留在程序目录，没有系统服务、注册表修改或开机自启动。删除前先停止服务，保留需要的观看数据库。

## 故障排查

- **无法启动**：确认 Node.js 版本及 8765 端口是否被其他程序占用，查看 `data/server-error.log`。
- **工具未安装**：运行“首次安装.cmd”，确认 `bin/ffmpeg.exe`、`bin/ffprobe.exe` 存在。
- **选择文件**：原生选择框会显示在浏览器前方。文件夹选择框每次选择一个，可重复添加；视频文件支持多选，也可直接粘贴完整路径。
- **部分文件无法读取**：确认磁盘在线、文件路径存在且当前用户有读取权限。
- **转换失败**：检查缓存所在磁盘的空间及写入权限，再检查日志。旧缓存可在“缓存管理”清理。

## 开发与验证

```powershell
npm ci
npm test
npm start
```

测试会生成短视频，验证本地 HTTP 接口、中文路径、Range、观看进度持久化及真实 FFmpeg 转换。另有使用真实 ArtPlayer 的 DOM 交互测试，模拟媒体事件验证续播与保存，不代替浏览器的真实解码和视觉检查。测试媒体写入系统临时目录，不会加入正式视频库。

服务只绑定 `127.0.0.1:8765`。接口检查本机 Host，并限制写接口的 Origin 和 JSON 内容类型；没有账号、局域网访问和云同步功能。

## 开源组件

- [ArtPlayer 5.4.0](https://github.com/zhw2590582/ArtPlayer)：MIT，使用其简体中文界面。
- [Express](https://expressjs.com/)：MIT，使用其文件响应处理 Range。
- [FFmpeg](https://ffmpeg.org/)：本交付的 Gyan essentials 构建启用 GPL；许可证及下载来源见 `bin/FFmpeg-LICENSE.txt`、`bin/FFmpeg-SOURCE.txt`。重新分发其二进制时应遵循相应许可证和源代码提供要求。
- [jsdom](https://github.com/jsdom/jsdom)：仅用于开发时的 DOM 交互测试，不参与网页运行。

各 npm 依赖许可证随 `node_modules` 一同保留。
